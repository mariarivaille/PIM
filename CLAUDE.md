# Pim

Pim — личный LLM-ассистент в Telegram (запись дел + напоминания). Python-пакет — `src/pim`. Архитектура и запуск — в README.md.

## Правила

- Слои: `telegram/` → `agent/` → `llm/`, `core/`; `reminders/` → `core/`. Ядро (`core`, `agent`, `reminders`) не импортирует aiogram.
- Время напоминания решает БД + `ReminderScheduler`, а не LLM.
- Даты тоже считает код: модель отдаёт `day`/`time`/`in_minutes`, `due_at` (ISO) — только для явной календарной даты.
  GigaChat ошибается с днями недели даже с календарём в промпте.
- Все datetime — aware; в БД UTC (`UTCDateTime`). От LLM — локальное ISO без смещения → `parse_local`.
- Новые инструменты агента — в `agent/tools.py`; JSON Schema без `anyOf`/`null` (ограничение GigaChat).
- Ошибки, которые модель может исправить, — `ToolError` (уходят модели как `{"error": ...}`).
- Тестируется на GigaChat, в проде — модели через OpenRouter; изменения в `llm/` проверять на обоих адаптерах.
- Окружение: `.venv` (Python 3.11), тесты `.venv/bin/pytest`.

## Память и пользователи

- Память (`memories`) целиком попадает в системный промпт; память скрытая: о сохранении/уточнении фактов бот отдельно не уведомляет, пользователь смотрит её сам (`/memory`, «что ты обо мне знаешь?»).
- Посреди разговора факт сохраняется только по явной просьбе: проверка `memory_requested` в `agent/tools.py` (слова-триггеры или «да» на «Запомнить это?»). Промпту модель следует ненадёжно — правила, которые важны, проверяем в коде.
- Остальное подбирает рефлексия (`memory/reflection.py`, задача планировщика): после `REFLECTION_IDLE_MINUTES` тишины разбирает неразобранные реплики (`users.reflected_until`), молча пишет факты с `source=inferred`. Выключается per-user (`users.auto_memory`).
- Пользователь видит факты по `memories.number` — своя нумерация у каждого, номера не переиспользуются. «удали факт N» выполняется без LLM (`agent/commands.py`).
- Ботом пользуются несколько людей: любой запрос к данным — с `user_id`, чужие записи недоступны (есть тесты на изоляцию). Сообщения одного пользователя обрабатываются по очереди (`Agent._locks`).
- Пересланные сообщения идут через `Agent.handle_forwarded`: текст оборачивается пометкой `FORWARD_MARK` (от кого, когда), относительные даты считаются от `ToolContext.reference_time` (момент отправки), «запомни» из чужого текста не считается просьбой пользователя.
- Тесты — на файловой SQLite (не `:memory:`), чтобы ловить проблемы параллельного доступа.
